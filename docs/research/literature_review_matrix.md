## How to use this matrix in the dissertation

- Use **XAI foundations** to justify SHAP/fallback explanations.
- Use **human-AI decision support** to justify the prediction-only vs explanation-supported evaluation.
- Use **conversational analytics** to position the Copilot chat and ambiguity handling.
- Use **AutoML/data preparation** to justify automatic cleaning and controlled model comparison.
- Use **responsible AI** to justify safety warnings, auditability and human review.
- Use **design science / DSS** to justify the artifact-building methodology.

## Gap coding summary

| Gap code | Meaning | Sources supporting it | Project response |
|---|---|---|---|
| G1 | Explanation-to-action gap | XAI papers explain predictions but rarely map them to business actions | SHAP/fallback drivers are translated into recommendations and warnings |
| G2 | Dataset-grounding gap | Conversational systems can be ambiguous or unsupported | Copilot answers only from active uploaded dataset and artefacts |
| G3 | Human-evaluation gap | XAI usefulness must be tested with users | Built-in Condition A vs Condition B evaluation workspace |
| G4 | Scale-readiness gap | Small prototypes often ignore large data | Scale Readiness tab and enterprise architecture documentation |
| G5 | Responsible recommendation gap | Decision support can cause overreliance | Safety warnings, HR caution and human-review framing |
